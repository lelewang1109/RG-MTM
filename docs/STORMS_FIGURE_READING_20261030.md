# Storms 首图的标注含义与改版建议（2026-10-30）

## 已核对的实现

逐小时 Storms 调用 `code/experiments/era5.py:scene_from_fields`，跨帧调用 `rgmtm.baselines.stmtm.match_leaves_by_overlap`。特征支撑样本由 `leaf_feature_vertices` 返回：极值顶点加所属叶弧的 regular vertices。相邻帧按稳定采样 ID 的交集计数构造矩阵，匈牙利算法选全局一对一匹配，再丢弃交集为零的配对。

因此，任意两个集合有交集不必然意味着获得同一个 ID；必须是最终选中的一对一匹配。这里的支撑集合也不应直接等同于完整气旋、任意等压线围成的区域、或另行计算的 watershed。特征 ID 是计算对应，不自动证明物理气旋身份连续。

## 点为什么仍有用

匹配对象是叶特征，极值点提供其位置代表。图中极值位置 p、参考投影 q、显示位置 x 用于揭示位置忠实度；跨帧身份已经由匹配输入固定。点不是匹配算法按距离追踪的网格粒子。不同预算列之间数据与 ID 不变，改变的是叶序、位置与显示合并层级。

显示轨迹同时包含参考点位置变化与布局残差：x(t)=q(t)+r(t)，所以 Δx=Δq+Δr。不能只凭彩色轨迹的斜率判定真实移动，也不能把它的跳动直接解释为物理跃迁。

## 针对现有二维 PPT 的建议（尚未改写原 PPT）

1. 首图核心问题改成“同一特征在不同预算下，离空间参考有多远，同时改变多少合并层级”。
2. (a) 月度概览只留 A/B 轨迹与局部时间框，说明它们是 matched leaf features。
3. (b) 五个空间快照可减到三个代表时刻。用淡色填充/轮廓显示程序实际的叶支撑采样集合 S_A(t)、S_B(t)，保留极值点和投影 q。若需要解释匹配，另加相邻两帧的支持集合重叠示意；集合要从实现读取，不能手绘替代。
4. (c) 每条特征叠加同色虚线 q(t) 和实线 x_epsilon(t)，只在同一个选定时间标点、菱形和连接段，直接看出 |x-q|。减少所有 A11/B11 等重复索引：颜色和行列时间负责对应关系，A/B 标签只出现于轨迹端点与关键帧。
5. (d) 固定同一时间显示原树与预算树，在变化的内部结点/合并层级处着色，并报告实际 d_top/Delta_F；结构深度只能辅助展示，不能替代误差证书或被解释为压力值。
6. 图例写清：填色集合=匹配支撑；圆点=位置代表/显示锚点（按面板区分）；菱形=空间参考 q；实线=显示位置 x；虚线=参考位置 q。图注注明基于支撑重叠的一对一匹配不是外部验证的气旋追踪真值。

本次是图件表达讨论。正式改版应另存原 PPT 的可编辑副本，保留原科学输入、显示配色和验证证据。
