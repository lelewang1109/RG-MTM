# 填充核验

直接执行当前代码rgmtm.baselines.stmtm.fill_frame，不是凭图猜顺序。固定示例叶序A,C,B,D，叶锚点4,10,13,19；区间[2,5],[9,10],[12,13],[17,20]；共23个显示采样。

1. 叶锚点先固定，再在区间内左右交替填叶弧常规样本。A的显示次序为a3,a1,A,a2；D为d3,d1,D,d2。
2. A–C间隙为S0,u2,u1；C–B间隙为S1；B–D间隙为u1,u2,S0。
3. 左边界为r2,r1；右边界为r1,r2。灰色标量/身份保持灰色，不再错误染成青绿色。
4. S0、u1/u2与r1/r2在不同路径重用，不是将源19节点强制一一映射为19个显示节点。R没有作为显式显示采样；这与当前边界路径采样实现一致。

verify.py构造与图一致的树、离散骨架和一组保持弧单调的示例标量，直接调用fill_frame，并独立逐对检查叶间区间最大值等于源LCA值。该例是Exact拓扑兼容叶序；预算放松时后续optimal_fill还可能改变间隙屏障值。一般像素数量不同会重采样弧值，所以不是所有参数下都强制23点。本图只说明一个明确的整数骨架填充例。

修改保留原树黑色连接和节点布局，重建的是错误的一维落点及其折线；每个显示采样均有来源节点。同一源节点可有多条折线。
